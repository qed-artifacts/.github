# Contributing to QED-AI public repositories

QED-AI welcomes careful improvements to its unrestricted public work. Before
opening an issue, commit, or pull request, confirm that every included file,
excerpt, screenshot, dataset, log, and piece of metadata is suitable for public
release.

Do not publish credentials, security configuration, residential addresses,
private correspondence, signatures, meeting recordings, Board records, legal or
tax working files, personal data, protected health information, or source material
whose license does not permit redistribution.

Domain portals are configuration-driven. Change domain content in `domain.json`,
register public browser applications in `apps/catalog.json`, and let the shared
QED-AI platform build the site. A domain repository should not copy or fork the
shared presentation layer unless an explicit architectural decision requires a
new platform boundary.

Public changes should preserve provenance, scope, limitations, uncertainty,
accessibility, and responsible-use language. Security and privacy concerns should
be reported privately under the organization security policy.
